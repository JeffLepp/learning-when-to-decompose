# WS2 — Activation-probe features (manager brief, phase A)

Worker: **`codex2`** (primary). Goal of phase A: a working, tested F3 feature pipeline (DESIGN_V2 §6) plus a feasibility probe on existing v1 labels. Then STOP and report.

## Tasks
1. **Environment `.venv-probe/`** (separate from locked `.venv`): Python 3.14 if PyTorch CUDA wheels exist for it, otherwise install a supported Python via the official installer route that already exists on this machine (check `py -0p`) — report what you chose. Need torch with CUDA support for RTX 5060 (Blackwell, sm_120 → CUDA 12.8+ wheels), transformers, accelerate, bitsandbytes (for 8B 4-bit), numpy, scikit-learn. Verify `torch.cuda.is_available()` and a tiny matmul on GPU. Write `requirements-probe-lock.txt` (pip freeze).
2. **Model matching**: for each Ollama model (`qwen3:0.6b, 1.7b, 4b, 8b`) call `POST /api/show` and determine which official Hugging Face checkpoint it corresponds to (Qwen3 base release vs. a later e.g. 2507 instruct/thinking variant — check architecture, parameter count, context length, chat template, and any metadata). Download the matching HF checkpoints to `hf_models/` (gitignored), recording repo id + revision sha. Report any mismatch honestly.
3. **`v2/probe/extract.py`**: given a domain items file and a prompt template (the S0 direct prompt as constructed by WS1's harness — import the prompt builder rather than copying it; if WS1's module isn't ready yet, write an adapter function with a clear TODO and a test that it matches once available), run a forward pass (no generation) with the chat template applied exactly as Ollama would format it for S0 (`think:false` → Qwen3's empty think block convention; verify against Ollama's template from /api/show). Save, per selected layers (e.g. every 4th layer + last), last-token and mean-pooled hidden states as float16 `.npy` under `results/v2/features/<domain>/<model>/`, with `index.json` (§5). Batch efficiently; hold `gpu_lock` for the whole job; ≤4B in bf16, 8B in 4-bit nf4. Record wall time and tokens processed (this is the router's overhead cost).
4. **Feasibility probe on v1 data**: the v1 8B runs give labels for 96 train + 32 validation + 32 audit + 24 dev SCAN commands (`results/train-8b-v1`, `validation-8b-v1`, `audit-8b-v1`, `pilot-8b-v1`). Extract 8B features for those commands using the **v1 direct prompt** (system=RULES + prompt as in v1 `experiment.py`), fit L2 logistic regression per layer predicting v1 decomposed-success, and report cross-validated AUROC per layer vs. the v1 structural features (`controller.py` features) — using only train+validation commands (do NOT use audit for any selection; you may report audit AUROC once at the end, clearly labeled as exploratory since v1 audit is already inspected). Small n — report CIs (bootstrap) and treat as feasibility only.
5. Tests in `v2/tests/test_probe_*.py` (CPU-only, tiny random model or mocked) for index alignment and file contracts.
